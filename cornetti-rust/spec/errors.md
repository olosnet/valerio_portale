# Module: errors (src/errors/)

## Purpose

Provides a centralized error factory system generated by the `define_errors!` proc macro
from `cornetti_macros`. Each subsystem's error variants are declared in a DSL file under
`src/errors/` and compiled into strongly-typed, zero-argument factory functions grouped
by HTTP status family.

The system produces a `crate::errors` module hierarchy (e.g. `errors::bad_request`,
`errors::conflict`, `errors::internal_server_error`) and an `error_catalog()` function
enumerating all defined errors.

Requires `cornetti_macros` (implicitly available when building `cornetti`).

## ADDED Requirements

### Requirement: Error factory DSL

The `define_errors!` macro SHALL accept a DSL with the following grammar:

```text
<category_name>(<status>, [log_level: <Level>]): {
    [*]<entry_name>[(<status_override>, [log_level: <Level>])] => "<detail_message>",
    ...
}
```

Each category SHALL become a `pub mod` containing one factory function per entry.
`*` prefix on an entry name SHALL mark the factory as having a placeholder
`internal_detail` (equal to the detail message), intended to be overwritten via
`.with_internal_detail(...)`. Entries without `*` SHALL have `internal_detail` set
to the detail message and left as-is.

The `corr_id` field SHALL be computed as `BE_<ENTRY_NAME_UPPERCASED>`.

`#[cfg(feature = "...")]` attributes on a category SHALL gate the entire generated
module behind the specified feature.

See DSL files in `src/errors/`: `body.rs`, `mongo.rs`, `redis.rs`, `mail.rs`,
`grpc.rs`, `sqlx.rs`, `auth.rs`, `auth_apikey.rs`, `filemanager.rs`, `gmail.rs`,
`templates.rs`.

#### Scenario: Category definition
- WHEN `define_errors!` processes `bad_request(400): { invalid_object_id => "Invalid ObjectId" }`
- THEN a module `bad_request` SHALL be generated with `pub fn invalid_object_id() -> CornettiError`
- AND the returned error SHALL have status 400, detail "Invalid ObjectId",
  corr_id "BE_INVALID_OBJECT_ID", and internal_detail "Invalid ObjectId"

#### Scenario: Entry with parameter placeholder
- WHEN an entry is prefixed with `*` (e.g. `*validation_error => "Validation error"`)
- THEN the generated function SHALL set `internal_detail` to "Validation error" as a placeholder
- AND the consumer SHALL be expected to call `.with_internal_detail(...)` to replace it

#### Scenario: Entry with status override
- WHEN an entry specifies an explicit status (e.g. `bson_error(400)`)
- THEN the generated function SHALL use the overridden status instead of the category default

#### Scenario: Entry with log_level override
- WHEN an entry specifies `log_level: Error`
- THEN the generated function SHALL set `log_level` to `Some(tracing::Level::ERROR)`

#### Scenario: Feature-gated category
- WHEN a category carries `#[cfg(feature = "mongo")]`
- THEN the entire generated module SHALL be gated behind `#[cfg(feature = "mongo")]`

### Requirement: Include file resolution

The `define_errors!` macro SHALL support `include!("path")` tokens that expand the
contents of the referenced file at macro evaluation time. The file path SHALL be
resolved relative to `CARGO_MANIFEST_DIR`.

See `cornetti/src/errors/mod.rs` and `cornetti_macros/src/lib.rs`.

#### Scenario: Include expansion
- WHEN `define_errors!` encounters `include!("src/errors/body.rs")`
- THEN the file contents SHALL be parsed as part of the DSL input

### Requirement: Error catalog

The `define_errors!` macro SHALL generate a `pub fn error_catalog()` function that
returns a `Vec<CornettiError>` containing one instance per defined error entry (all
features enabled). Every entry SHALL have a non-empty `corr_id` in the format
`BE_<NAME>`.

See `error_catalog` in the expanded output.

#### Scenario: Catalog contains all entries
- WHEN `error_catalog()` is called
- THEN the returned vector SHALL contain every defined error variant
- AND every error SHALL have a non-empty `corr_id`

### Requirement: JSON error export

The `export_errors_json!` macro SHALL generate a `server-errors.json` file in
`CARGO_MANIFEST_DIR` at compile time, mapping `corr_id` to `detail` for all
defined errors in a flat JSON object.

See `cornetti_macros/src/lib.rs`.

#### Scenario: JSON export at build time
- WHEN `export_errors_json!` is invoked with the same DSL input as `define_errors!`
- THEN a `server-errors.json` file SHALL be written to the crate root
- AND it SHALL contain `{ "BE_INVALID_OBJECT_ID": "Invalid ObjectId", ... }`

### Requirement: From conversions in errors/mod.rs

The `errors/mod.rs` module SHALL provide `From` implementations for core library
error types (`serde_json::Error`, `validator::ValidationErrors`, `std::io::Error`)
that delegate to the generated factory functions with `with_internal_detail(...)`
containing the original error string.

See `cornetti/src/errors/mod.rs`.

#### Scenario: serde_json::Error conversion
- WHEN a `serde_json::Error` is converted via `From`
- THEN a `CornettiError` with status 500, detail "Serialization error", and
  corr_id "BE_SERIALIZATION_ERROR" SHALL be returned
- AND `internal_detail` SHALL contain the original error message
